# 原终端命令与便携版本

你的原命令执行四件事：设置组别；递归查找桌面新版 b1_sources；查找最新启动器并复制到 Documents 中的实验目录；用 Group 参数启动。

它是本机更新与启动命令，不是网页生成程序，也不是收集参与者数据的程序。换电脑后，固定 Documents 路径和“搜索整个桌面”不可靠；本包已把两份离线 HTML 与该启动器放在一起，因此只需要根目录 Start-AccessWiki.ps1。

## 验证而不打开网页

在包的根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\Start-AccessWiki.ps1" -Group G6 -ValidateOnly
```

成功时输出 12 个绑定及 VALIDATION_OK。它检查文件解析，不证明音频播放、读屏表现或现场流程正确。

## 常见情况

- 不要在 ZIP 预览窗口直接启动，必须先完整解压。
- 找不到脚本：确认终端当前文件夹含 Start-AccessWiki.ps1。
- 编号与组别不符：用 README 中对应编号，启动器不会接受任意编号。
- 没有 NVDA：仍可以查看网页和播放音频，但不能等同于原读屏测试。
- 医院来源快照缺少部分原站样式与脚本；正文可用性仍需实际读屏核验。
- 网页入口不更改或替代原实验顺序；错误音频是故意改写的研究刺激，不作为服务指南。

## 找不到 Start-AccessWiki.ps1

`PS C:\Users\YOUR_NAME>` 表示当前在用户主目录。命令里的 `.` 是当前目录，不是下载或解压目录，所以相对路径会找不到文件。这不表示材料包或 PowerShell 损坏。

最简单的处理是完整解压后双击 `Launch-AccessWiki.cmd`。它使用自身目录定位脚本。如果仍用终端，可以先进入解压目录，也可以给 `-File` 指定脚本的完整路径。

## 现场手动操作

研究者于 2026-09-26 补充确认：现场由研究者手动切换音频，以推进访谈进度；听完音频后还需提问等，过程中会打断参与者的触摸操作。因此，启动器菜单仅是材料调用工具，不能用默认菜单顺序重建现场实际播放时间线。本次不改写原有音频选择逻辑，也不把流程描述为自动连续播放或完全独立操作。该确认没有提供逐人逐轮的文件及时间日志。
